# AI Agent — Personal Assistant

Клиентское веб-приложение: персональный AI-агент с поддержкой tool-calling, работающий целиком в браузере. Без бэкенда, без рантайм-зависимостей — только нативные Web API; для разработки и запуска сборка тоже не нужна (см. «Быстрый старт»). Данные хранятся локально в IndexedDB, запросы идут напрямую к любому OpenAI-совместимому API.

Для раздачи наружу есть отдельный необязательный шаг — продакшен-сборка с обфускацией в `dist/` (см. ниже).

## Возможности

- **Чат с LLM** — потоковый вывод (streaming), поддержка любого OpenAI-совместимого эндпоинта; переключение между чатами во время генерации ответа не рвёт визуализацию и не путает, в какой чат что записано
- **Провайдеры и модели** — несколько провайдеров, у каждого свой набор моделей; быстрое переключение прямо в чате, и у каждого чата свой набор моделей для этого
- **Tools** — встроенные инструменты, инструменты со своим JS-кодом и подключение внешних MCP-серверов
- **Самораcширение** — агент умеет создавать и редактировать собственные инструменты, skills и промпты по ходу диалога
- **Skills** — наборы системных промптов, включаемые переключателем прямо в чате
- **Библиотека промптов** — шаблоны с подстановкой переменных `{{var}}`
- **Файлы** — ссылки на файлы диска через File System Access API, без копирования содержимого
- **Папки** — произвольная вложенная иерархия для чатов/tools/skills/промптов/файлов с drag-and-drop
- **Политики безопасности** — режимы подтверждения действий агента от «отключено» до «максимальный», белые списки доменов и MCP-серверов, журнал решений
- **Голосовой ввод** — диктовка сообщений через Web Speech API
- **Статистика** — израсходованные токены, размер контекста и метрики вызовов инструментов по каждому чату
- **Экспорт/импорт** — зашифрованный паролем архив с сохранением структуры папок; отдельно — экспорт/импорт самих чатов (html/json/markdown/excel, поиск по всем чатам)

Отдельная установка не требуется — приложение статическое.

```

js/core/markdown.js
js/core/agent.js
js/llm/llm-gateway.js
js/llm/llm-registry.js
js/tools/tools-engine.js
js/tools/tools-registry.js
js/tools/tools-executor.js
js/tools/tools-builtin.js
js/tools/tools-defs.js
js/tools/tools-mcp.js
js/tools/tools-llm-router.js
js/engines/skills-engine.js
js/engines/prompts-library.js
js/engines/folders-engine.js
js/engines/files-engine.js
js/engines/security-engine.js
js/ui/ui-core.js
js/ui/ui-navigation.js
js/ui/ui-chat.js

```

`js/` разложен по подпапкам по **роли кода**, а не по предметным группам —
тот же принцип, что уже применён к разбивке `tools-*.js` и `ui-*.js` внутри
самих файлов:

| Подпапка | Что в ней |
|---|---|
| `core/` | БД, оркестратор, шифрование, markdown — то, на чём держится всё остальное |
| `llm/` | Клиент API и реестр провайдеров/моделей |
| `tools/` | Движок инструментов и все его модули (реестр, исполнение, встроенные tools, MCP) |
| `engines/` | Независимые движки без общего префикса файлов — навыки, промпты, папки, файлы, безопасность |
| `ui/` | Интерфейс — единый класс `UI`, разнесённый по файлам-примесям |
| `tests/` | Функциональные тесты на Node (`vm`-песочница, без браузера) |

Порядок подключения в `index.html` важен: `crypto-utils.js` — после `db.js`, `tools-engine.js` — перед остальными `tools/*.js` (тот же приём примесей, что и у `ui/*.js`), `ui-core.js` — перед остальными `ui/*.js` (он объявляет класс, который те дополняют), а `agent.js` — после всех движков. Порядок между подпапками не поменялся при переносе — сменились только пути, ни один файл не переименован.

Разложив файлы, откройте `index.html` через локальный веб-сервер:

```bash
python3 -m http.server 8000
```

Затем перейдите на `http://localhost:8000` и в ⚙ **Настройки → Провайдеры и модели** добавьте провайдера (API URL, ключ, способ авторизации) и его модели — кнопкой «Загрузить у провайдера» (запрос `/models`) или вручную.

> Открытие через `file://` работать не будет: голосовой ввод и часть Web Crypto API требуют защищённого контекста (HTTPS или localhost).

## Продакшен-сборка

Для разработки сборка не нужна — см. «Быстрый старт» выше. Но для раздачи
наружу есть отдельный, необязательный шаг: `dist/` — самодостаточная
папка с одним обфусцированным JS-бандлом вместо 27 читаемых файлов.

```bash
npm install     # один раз — тянет devDependency javascript-obfuscator
npm run build   # собирает dist/index.html, dist/app.min.js, dist/css/styles.css
```

Скрипт сборки (`scripts/build-prod.js`) сам вычитывает порядок `<script>`
из `index.html` и склеивает файлы в этом же порядке в одну строку —
поведение не меняется, файлы и так делят один глобальный scope. Дальше
результат обфусцируется **одним проходом**, а не файл за файлом: у классов
вроде `ToolsEngine` или `UI` имя должно остаться одинаковым между файлом,
где класс объявлен, и файлами, что дополняют его прототип — обфускация по
отдельности почти гарантированно рассинхронизировала бы эти имена и
сломала бы приложение без единой ошибки при сборке.

Переименование верхнеуровневых имён (`renameGlobals`) выключено намеренно:
это не только связки между файлами, но и точка входа для отладки прямо в
консоли браузера (`agent.tools.debug = true`, `agent.llm.debug = true`).
Обфускация локальных переменных, строк и структуры внутри функций работает
как обычно и даёт основной эффект.

`dist/` коммитится в репозиторий как есть — вместе с `node_modules/`
инструмент сборки не нужен, чтобы просто раздать готовый продакшен-бандл
любым статическим веб-сервером.

## Архитектура

Приложение построено на классах в глобальной области видимости, без модулей и сборщика. Точка входа — `app.js`, создающий `AIAgent`, который поднимает остальные подсистемы.

Интерфейс разнесён по нескольким файлам `ui-*.js`, но остаётся **единым классом `UI`**: `ui-core.js` объявляет класс, остальные дополняют его через `Object.assign(UI.prototype, {...})`. Это позволяет разделить код по смыслу, не вводя сборщик и не меняя способ подключения через `<script>`.

| Файл | Класс | Назначение |
|---|---|---|

### Хранилище

IndexedDB `ai_agent_db`, версия схемы **10**:

| Store | Ключ | Содержимое |
|---|---|---|
| `chats` | `id` | Чаты: заголовок, даты, папка (`parentId`), набор моделей (`modelRefs`/`modelRef`) |
| `messages` | `id` | Сообщения, включая tool-вызовы и их результаты |
| `tools` | `id` | Инструменты: встроенные, кастомные, MCP |
| `skills` | `id` | Skills с системными промптами |
| `prompts` | `id` | Шаблоны промптов |
| `folders` | `id` | Папки для всех разделов, включая чаты и файлы (поле `type`) |
| `files` | `id` | Ссылки на файлы: метаданные и дескриптор, без содержимого |
| `llm_connections` | `id` | Провайдеры LLM с вложенными моделями (ключ и заголовки зашифрованы) |
| `mcp_servers` | `id` | Подключённые MCP-серверы: имя, URL, токен (зашифрован), ссылка на папку-контейнер |
| `settings` | `key` | `llm_registry`, `limits`, `display`, `logging`, `context`, `layout`, `security` |
| `chat_stats` | `chatId` | Токены, размер контекста и агрегаты вызовов инструментов |

## Инструменты (tools)

### Встроенные

`get_current_time` · `calculator` · `http_fetch` · `format_json` · `format_xml` · `generate_password` · `persistent_memory` · `ask_user` · `list_workspace` · `export_chat` · `import_chat` · `export_chats` · `import_chats` · `search_chats` · `list_files` · `read_file` · `search_files` · `chat_folder` · `move_chat` · `explain_agent` · `diagnose` · `import_skill_from_text`

Управление подключением к LLM: `llm_list`, `llm_status`, `llm_switch`, `llm_test` — читают и меняют модель **текущего чата**; секреты через них не отдаются.

Отдельная группа — инструменты самомодификации, которыми агент управляет собственной конфигурацией: `create_tool`, `update_tool`, `create_skill`, `update_skill`, `create_prompt`, `update_prompt`, `create_folder`, `rename_folder`, `move_folder`, `delete_folder`, `move_item`.

### Кастомные

Инструмент задаётся именем, описанием, JSON Schema параметров и `handlerCode` — телом JS-функции, получающей объект `params`. Код компилируется заново при каждом вызове, поэтому правки применяются без перезагрузки страницы.

### MCP-серверы

Сервер — отдельная сущность (`mcp_servers`), а не просто повторённый на каждом его tool URL. Подключение (кнопка «+ MCP Server» на вкладке Tools) спрашивает название, адрес и токен, импортирует инструменты через `tools/list`; вызовы проксируются через JSON-RPC `tools/call`, обработчики восстанавливаются при каждом старте приложения.

В дереве раздела Tools сервер — узел 🧩 со своей папкой-контейнером; все его инструменты живут внутри, организовать их можно произвольной вложенной иерархией подпапок. Название и токен сервера редактируются (адрес — нет, он совпадает с `mcpServer` у уже импортированных tools); удаление сервера убирает его целиком — все инструменты и подпапки. Перетащить инструмент или папку так, чтобы смешать содержимое разных серверов (или сервера с обычными папками), нельзя — перемещение отклоняется, если области видимости источника и цели не совпадают.

## Провайдеры и модели

Двухуровневая настройка: **провайдер** — адрес API, ключ, способ авторизации; **модель** — идентификатор, класс сложности, окно контекста, `max_tokens`, температура. Модели вложены в запись провайдера. Модели можно подтянуть списком у провайдера (`/models`) или добавить вручную.

При добавлении модели `max_tokens` по умолчанию равен окну контекста и следует за ним, пока поле не тронуто руками, — уменьшите вручную, если нужен меньший потолок длины ответа.

У каждого чата — свой короткий набор моделей для быстрого переключения (кнопка «+ модель» в панели чата), из которого выбрана ровно одна активная. Наборы у разных чатов независимы.

### Переключение между чатами во время генерации ответа

Состояние хода (стриминг, статус-панель, счётчики) привязано к конкретному чату, а не к приложению в целом: пока один чат ждёт ответ модели, можно свободно смотреть любые другие — их отрисовка не пострадает, а при возврате в отвечающий чат восстановятся и уже полученный текст, и индикатор хода. Общий шлюз LLM обслуживает один запрос за раз — попытка отправить сообщение в другом чате в это время не срабатывает молча, а показывает, в каком именно чате идёт ответ. В списке чатов отвечающий сейчас чат помечен спиннером.

## Настройки

Модальное окно ⚙ (открывается строго — клик мимо не закрывает, чтобы не терять несохранённые правки) разделено на вкладки:

- **🔌 Провайдеры и модели** — список провайдеров и их моделей, порог предупреждения о заполнении контекста
- **⏱ Ограничения** — лимиты работы агента при вызове инструментов
- **👁 Отображение** — детализация вывода tool-вызовов, навыки и файлы в контексте чата
- **🛡 Безопасность** — режим подтверждения операций агента, белые списки доменов и MCP-серверов, потолки изменений, журнал решений
- **🪵 Журналирование** — подробные логи запросов к LLM и вызовов инструментов в консоль

### Ограничения работы агента

Применяются к одному ответу — всей цепочке вызовов, запущенной сообщением пользователя. Значение `0` отключает лимит.

| Параметр | По умолчанию | Назначение |
|---|---|---|
| Итерации tool-calling | 25 | Защита от зацикливания модели на вызовах |
| Бюджет времени на ответ | 180 с | Прерывает запрос через `AbortController` |
| Таймаут одного инструмента | 30 с | Зависший инструмент вернёт ошибку вместо блокировки |
| Вызовов за ответ | 50 | Суммарный потолок |

## Экспорт чата и поиск

Инструмент `export_chat` выгружает переписку с хронологией в один из форматов:

| Формат | Что получается |
|---|---|
| `html` | Самодостаточный документ со встроенными стилями, готовый к просмотру |
| `json` | Структурированные данные со статистикой чата |
| `markdown` | Текст с заголовками ролей и блоками кода |
| `excel` | Таблица: время, роль, содержимое, вызовы инструментов, длительность |

Оговорка про `excel`: настоящий `.xlsx` — это ZIP-контейнер с XML внутри, собрать
его в браузере без внешней библиотеки нельзя. Выгружается HTML-таблица с расширением
`.xls`, которую Excel и LibreOffice открывают штатно.

Инструмент `search_chats` ищет подстроку по всем чатам (или в одном), возвращая
фрагменты вокруг совпадений с указанием чата, роли и даты. Поиск буквальный, не
семантический; есть фильтры по роли автора и учёту регистра.

## Экспорт и импорт

Кнопки «📦 Экспорт» и «📥 Импорт» находятся в шапке каждой панели (Tools, Skills, Промпты) и работают со своим разделом. Экспорт учитывает текущую папку: можно выгрузить только её, её вместе с вложенными или весь раздел, отметив конкретные объекты галочками.

Архив вместе со структурой папок шифруется паролем: **PBKDF2-SHA256 (250 000 итераций)** → **AES-GCM-256**. Файл открывается на любой машине — ключ выводится из пароля, а не из локального хранилища.

При экспорте встроенные инструменты пропускаются (создаются автоматически при запуске), а токены MCP-серверов вырезаются из архива. При импорте доступны режимы «добавить» и «перезаписать».

## Безопасность

### Политики подтверждения

Перед выполнением любого инструмента `security-engine.js` классифицирует
операцию по последствиям (чтение, изменение, удаление, сеть, исполнение
кода, смена модели) и решает, нужно ли подтверждение — по режиму,
выбранному во вкладке 🛡 **Безопасность**: от «отключено» до «максимальный»
(где `create_tool`/`update_tool` запрещены агенту полностью, а сеть — только
по белому списку). У MCP-вызовов отдельная, более строгая категория: ответ
чужого сервера уходит прямо в контекст диалога. Все решения — разрешено,
отклонено, заблокировано — попадают в журнал.

Граница механизма: политики ограничивают действия **через инструменты**, но
не изолируют код уже включённого инструмента — тот выполняется в браузере и
может обратиться к сети напрямую. Поэтому созданный моделью инструмент
всё равно включает пользователь вручную.

### Что реализовано на уровне кода

- **Экранирование HTML** в markdown-рендерере — ответ модели не может выполниться как разметка, ссылки с `javascript:`/`data:` блокируются
- **Инструменты создаются выключенными.** Инструмент, созданный или изменённый моделью, требует ручного включения пользователем — модель не может одним вызовом написать код и сразу его запустить
- **Шифрование секретов.** API-ключи и MCP-токены хранятся в IndexedDB зашифрованными (AES-GCM, ключ non-extractable), а не открытым текстом
- **Ограничение `http_fetch`.** Заблокированы не-HTTP(S) протоколы и обращения к `localhost`, приватным подсетям и cloud-metadata адресам
- **Логирование выключено по умолчанию** — иначе переписка и аргументы инструментов писались бы в консоль

Известные ограничения, о которых стоит знать:

- **`handlerCode` исполняется без песочницы** — через `AsyncFunction` в основном контексте страницы, с доступом к `fetch` и `window`. Подтверждение пользователем снижает риск, но не изолирует код. Полная изоляция требует Worker или sandboxed iframe.
- **Шифрование секретов не защищает от XSS** в том же источнике: код на странице может вызвать расшифровку так же, как это делает приложение. Защищает от просмотра БД через DevTools, расширения и бэкапы профиля.
- **Таймаут инструмента не прерывает синхронный код** — JS не умеет прерывать выполняющуюся функцию. Зависший в цикле handler продолжит занимать поток.
- **SSRF-фильтр не защищает от DNS rebinding** — проверяется имя хоста из URL, а не итоговый IP соединения.
- **Стойкость архива определяется паролем** — PBKDF2 замедляет перебор, но слабый пароль остаётся слабым.

Радикальное решение первых двух пунктов — вынести вызовы LLM и исполнение инструментов на серверный прокси, чтобы секреты и чужой код вообще не попадали в браузер.

## Требования

Современный браузер с поддержкой IndexedDB, Web Crypto API и ES2020. Голосовой ввод работает в Chrome и Edge (в Firefox Web Speech API по умолчанию отключён) и требует HTTPS или localhost.

Счётчик токенов зависит от провайдера: в потоковом режиме запрашивается `stream_options: {include_usage: true}`, и если API это поле игнорирует, статистика токенов останется пустой.
